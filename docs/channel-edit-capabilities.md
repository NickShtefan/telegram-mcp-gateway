# Channel editor capability matrix

Matrix revision **2**. Scope is existing broadcast channel posts and their Telegram schedule queues. The baseline tree is [`f460d73`](https://github.com/NickShtefan/telegram-mcp-gateway/commit/f460d730806df172b681fb3b204ff1976027d5b9), after issue [#12](https://github.com/NickShtefan/telegram-mcp-gateway/issues/12) PRs #14, #16, #18, #19 and #20. This baseline pins `teleproto@1.229.1`, with MTProto layer **229** as declared by `teleproto/tl/runtime/registry`. Source qualification applies to the recorded build and Telegram account. A TL constructor or method definition alone does not establish a live result.

**Live** means the operation passed on an owner-authorized Telegram test post with read-back. **Fixture** means an automated gateway or serialized MTProto test passed. **Refusal** means the caller gets an explicit limit or rights error for the relevant request. The live evidence below applies to the stated subcases.

## Bot keyboard live evidence

The fixture was published on `aeba5fb`. Telegram returned an outgoing broadcast post without `from_id` for the authenticated bot. The same session read two neighboring posts as incoming. After the authorship correction, the bot changed the label and destination from **Telegram** (`https://telegram.org/`) to **Telegram FAQ** (`https://telegram.org/faq`). Telegram rejected an empty inline keyboard with `REPLY_MARKUP_INVALID`. The corrected markup-only request omitted the optional markup field, and the bot cleared the keyboard from the same message. A separate user-session read found the original test text and an empty keyboard. [Telegram message fields](https://core.telegram.org/constructor/message) · [TDLib keyboard editing](https://github.com/tdlib/td/blob/master/td/telegram/MessagesManager.cpp#L22257-L22278)

## Permission and test evidence

A profile needs the write toolset and write capability, an active account grant and an allowed chat. These gateway checks are separate from Telegram's channel posting and editing rights, bot authorship, timing and Premium rules. Telegram remains authoritative. Uncertain observed results require a read-only status check. A new owner decision is required before retrying with different content.

The cross-client scenarios ran on in-memory Telegram fixtures from Codex and OpenCode. Claude Code was attempted but stopped on expired OAuth before reaching the fixture. The latest merged catalog recorded **11** core tools, **18** core + write tools and **24** across all toolsets. Core + write serialized to **24,916 bytes** on `606441a`, compared with **22,550 bytes** at the issue's baseline. The frozen ordinary-read comparisons remained equal. These are wire measurements. [Latest qualification](https://github.com/NickShtefan/telegram-mcp-gateway/pull/20)

When recording a live result, include the exact commit, SDK and layer, Telegram account type, affected operation and verification outcome. Keep credentials, raw file references, session data and private account state out of the evidence. See [tools and edit flags](tools.md#edit-text-formatting-and-captions) and [the synthetic and live procedures](scenarios.md).

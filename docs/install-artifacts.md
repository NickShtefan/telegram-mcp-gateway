# Signed installer artifacts

A release has five platform archives, two bootstrap scripts and SHA256SUMS; every asset name carries the release name from the tag (for example `telegram-mcp-gateway-0.2.0-macos-arm64.tar.gz`, or `telegram-mcp-gateway-0.2.0-test.1-...` for a test draft). User transport is canonical flat USTAR gzip on POSIX and ZIP on Windows. Each archive contains exactly nine regular files: manifest.tsv, manifest.sig, signer.der, the standalone Node binary, installer/manifest/archive helpers, application.tar.gz and NODE_LICENSE. Unknown names, directories, links, duplicate entries, oversize data and malformed transport are rejected before anything reaches an installation path.

The ASCII versioned manifest binds 0.2.0, source SHA, OS/architecture, exact Node version, six fixed payload names, sizes and SHA-256. Detached RSA-3072/SHA-256 PKCS#1 signatures use the owner-pinned DER certificate. The certificate is a public-key container, not Apple notarization/Windows Authenticode or CA trust.

Bootstrap is the initial trust root. README pins the SHA-256 of the current bootstrap bytes (a test recomputes them), and its install command checks a protected copy against that value before executing it. Authenticate README independently: a substituted package page cannot substitute the pinned verifier, but compromised repository/README or local OS remains a limitation. Without a pin the source SHA is derived only after manifest signature verification, before payload execution, so any owner-signed 0.2.0 build is accepted; the release-notes commands pass the exact source commit and the bootstrap then rejects every other build. No user hash entry, signing key or preinstalled Node is required.

POSIX snapshots use bounded no-follow/nonblocking descriptors and single-link checks. The gzip/tar transport reader allows only fixed regular basenames with strict headers, sizes, padding and an overall deadline/budget; it writes only to private staging. Windows reads one bounded native file handle and checks regularity, link count and resolved path; ZIP entries are fixed/bounded and checked before protected staging. Privileged child environments exclude Node injection variables. Complete Windows staging ancestry and administrator/System ACLs are attested before staged execution.

The application reader validates a narrower canonical USTAR archive before writes, rejecting traversal/collisions/ADS/reserved names, links/devices, unsafe execution and unbounded decompression. Windows attests unique empty paths in bounded batches before writing payloads; POSIX uses exclusive protected writes. Partial staging is not a completed service.

Official Node versions and whole upstream archive digests are pinned in scripts/install/runtime-catalog.json. Builder acquisition checks those digests before entry extraction or host-matching execution; bundling independently re-extracts/compares Node/license bytes. CI never signs production packages. [Owner draft preparation](release-qualification.md) validates every candidate against CI log manifest hashes and uses one hidden owner passphrase for all five.

No signing key, Telegram session, API credentials or bearer is packaged. Source/fixture tests and signed packaging do not prove actual fresh installation or model-client tools. Record live evidence through [README-only acceptance](outsider-test.md).
